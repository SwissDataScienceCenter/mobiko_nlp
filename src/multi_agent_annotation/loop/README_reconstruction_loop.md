# Cold-start guideline reconstruction loop (RQ-D)

Closed-loop experiment that asks: **can deliberation friction reconstruct expert
disambiguation rules from a cold start?** Starting from a guideline + decision
table that contain only entity-type names and one-line definitions, the loop
repeatedly annotates a working set, mines the confusions the agents argue about,
drafts operational disambiguation rules from those confusions, and folds them
back into both artifacts — with no human in the loop.

Implements spec §11 (G0 cold start, the iteration loop, the amender, the
programmatic approval gate, **and the dual stopping rule §11.3** — see
[Stopping rule](#stopping-rule-113) below). See `project memory` / the spec for
the full RQ-D framing.

> **Layout:** the loop scripts live in `src/multi_agent_annotation/loop/`; the
> evaluation scripts in `src/multi_agent_annotation/evaluation/`; the shared core
> (`multi_agent_annotation_ag2.py`, `deliberation_history.py`, `prompts.py`,
> `demo_ag2.py`) stays at the package root `src/multi_agent_annotation/`. Every
> script is cwd-independent (it bootstraps its own import paths).

> **Interpreter:** run everything with the project venv that has the pipeline
> deps (`ag2`/`autogen`, `openai`, `sentence-transformers`):
> `…/mobiko_nlp/.mobiko-venv/bin/python`. The other venv (`.venv`) is missing
> them. All commands below assume `cwd = src/multi_agent_annotation/loop/`
> (so the venv is `../../../.mobiko-venv/bin/python`).

## The files — and which you actually run (all under `loop/`)

| File | You run it? | Role |
|------|-------------|------|
| **`reconstruct_loop.py`** | **Yes** — this is the experiment | Orchestrator: drives every iteration (annotate → mine → metrics → **stop check** → amend → apply). |
| **`cold_start_init.py`** | Optionally, once, first | Generates the cold-start `G0.md` + `D0.csv`. Skip it and the loop auto-generates them. |

| `guideline_amender.py` | No — the loop imports it | Library + standalone CLI: drafts one operational amendment per confusion (the approval gate). |
| `stopping_rule.py` | No — the loop imports it | Library: the dual stopping rule (§11.3) — friction, held-out F1, text delta, rule coverage, and `decide_stop`. |

```
cold_start_init.py ─┐ (or auto-generated by the loop)
                    ├─► reconstruct_loop.py ──subprocess──► cold_start_annotate.py
```

## Run order

### Step 1 (optional) — generate & review the cold start

```bash
../../../.mobiko-venv/bin/python cold_start_init.py \
    --out-dir ../../../output/recon/coldstart
# → writes G0.md + D0.csv (16 entity types, one-line defs only;
#   Question/Examples columns blank). Review/tweak before running.
```

Skip this if you're happy for the loop to generate them automatically.

### Step 2 — run the loop (with the dual stopping rule)

```bash
../../../.mobiko-venv/bin/python reconstruct_loop.py \
    --working-jsonl ../../../data/auto_annotated/<working_set>.jsonl \
    --out-dir       ../../../output/recon \
    --i-max 6 --top-k 5 --min-count 5 \
    --annotator-model   qwen3-35B-vllm \
    --critic-model      qwen3-35B-vllm \
    --adjudicator-model qwen3-35B-vllm \
    --amender-model     qwen3-35B-vllm \
    --held-out-jsonl ../../../data/heldout/heldout_sentences.jsonl \
    --held-out-human ../human_annotated/combined_M_D_Mark_latest_wins.json \
                     ../human_annotated/combined_M_D_Davnah_latest_wins.json \
    --held-out-names Mark Davnah \
    --expert-rules   ../../../data/expert_disambiguations.json
```

- Pass `--g0 …/coldstart/G0.md --d0 …/coldstart/D0.csv` to use the artifacts you
  reviewed in step 1. **Omit both** and the loop generates them into
  `<out-dir>/coldstart/`.
- **Stopping rule (§11.3):** `--held-out-jsonl`/`--held-out-human` enable the
  echo-chamber GUARD; the friction-convergence PRIMARY stop runs regardless.
  Omit the held-out flags and the guard is disabled (a loud warning is logged) —
  the loop then stops on friction convergence + the hard stops only.
  `--expert-rules` is optional (the §11.5b coverage curve, monitoring only).
- Smoke test: add `--num-sentences 3 --held-out-num-sentences 3 --i-max 1`.
- Re-run after an interruption with `--resume` (re-mines metrics from existing
  logs so the trajectory + stop decision stay correct; skips re-annotation/draft
  only once an iteration's deliberations actually cover every expected
  sentence — a partially-annotated file from a crash is completed, not reused
  as-is). **Without `--resume`, a re-run wipes and redoes annotation from
  scratch** — always pass it when recovering from a break.
- A crashed annotation subprocess (flaky endpoint, OOM, …) is retried
  automatically within the same iteration — see `--subprocess-retries` below;
  every retry forces `--resume` on the subprocess so sentences it already
  flushed aren't redone. This is orthogonal to the top-level `--resume` flag,
  which is about resuming a whole *loop* invocation, not a single annotation
  call.

## Inputs

| Flag | Default | Meaning |
|------|---------|---------|
| `--working-jsonl` | *(required)* | Working-set sentences; JSONL with a `sentence` or `text` field per line. |
| `--out-dir` | *(required)* | Run directory (everything is written here). |
| `--g0` | auto-generate | Cold-start guideline (`.md`). |
| `--d0` | auto-generate | Cold-start decision table (`.csv`). |
| `--schema` | `../../resources_updated/relation_schema.py` | Relation schema (fixed across the experiment). |
| `--seeds` | `../../resources_updated/manual_seeds_filled.py` | Seed examples. |
| `--i-max` | `6` | Hard iteration cap. |
| `--top-k` | `5` | Top confusions amended per iteration. |
| `--min-count` | `5` | Minimum confusion occurrences to amend (spec: ≥ 5). |
| `--patterns` | `entity` | `entity` = reconstruct entity-type disambiguation only (relations fixed, spec 11.1); `all` = also amend relation/scope confusions. |
| `--max-redrafts` | `2` | Redrafts when a decision test fails the operationality gate. |
| `--examples-per-pattern` | `5` | Concrete examples mined per confusion to ground the amender. |
| `--amender-model` | `qwen3-35B-vllm` | Amender LLM — any `MODEL_ENDPOINTS` key (`gpt4o`, `qwen3-35B-vllm`, `swissai-qwen3.5-27B`, `swissai-gemma-31B`, `swissai-apertus-70B`, …). |
| `--annotator/critic/adjudicator-model` | `qwen3-35B-vllm` | Annotation models (fixed across iterations). |
| `--max-rounds` | `2` | Annotator↔Critic rounds per sentence. |
| `--num-sentences` | all | Cap the working set (smoke tests). |
| `--leak-ngram` | `7` | Word n-gram length for the corpus-leak safety check. |
| `--python` | current interpreter | Python used for the annotation subprocess. |
| `--resume` | off | Skip stages whose outputs are actually complete (not just present). |
| `--subprocess-retries` | `3` | Retries for a crashed annotation subprocess within one iteration; each retry forces `--resume` so already-annotated sentences aren't redone. `1` disables retrying. |

Annotation passthrough flags also exist: `--guideline-search {mandatory,optional}`,
`--guideline-search-backend {lexical,embedding}`, `--strict-critic`,
`--no-relation-schema-in-prompt`, `--tool-choice`, `--precedent-memory`, `--timeout`.
(`--no-relation-schema-in-prompt` drops the `## Relation Schema` section from the agent
system prompts; the schema is still loaded from `--schema` and served by `schema_lookup`.)

### Stopping-rule flags (§11.3)

| Flag | Default | Meaning |
|------|---------|---------|
| `--held-out-jsonl` | none | Held-out split sentences (JSONL). **Must be distinct from `--working-jsonl`** (§11.7). Enables the F1 GUARD. |
| `--held-out-human` | none | Expert gold file(s) for the held-out split (native project JSON or per-annotator JSONL). Required for the guard. |
| `--held-out-names` | file stems | Display names for the expert files, in order (e.g. `Mark Davnah`). |
| `--held-out-f1-mode` | `strict` | Matching for the held-out F1: `strict` (offset+type), `boundary` (offset), `text_type`, `text_only`. |
| `--held-out-num-sentences` | all | Cap the held-out size (smoke tests). |
| `--stop-friction-eps` | `0.05` | PRIMARY: max relative reduction in R1 disagreements that counts as "converged" (spec: < 5%). |
| `--stop-friction-patience` | `2` | PRIMARY: consecutive sub-eps iterations required to stop. |
| `--stop-f1-guard-patience` | `2` | GUARD: consecutive held-out-F1 decreases that trip the echo-chamber guard. |
| `--no-stopping-rule` | off | Log all §11.3 metrics but **don't** stop on them (run to `i_max` / hard stops). For ablations. |
| `--no-embedding-drift` | off | Skip the monitoring-only embedding-similarity drift in the text delta. |
| `--expert-rules` | none | Enumerated expert disambiguations (JSON/CSV) for the §11.5b coverage curve (monitoring only). |
| `--rule-coverage-semantic` | off | Also score semantic coverage (embedding match of expert-rule text vs reconstructed `decision_test`), not just label-pair coverage. |
| `--rule-coverage-threshold` | `0.5` | Cosine threshold for `--rule-coverage-semantic`. |

**`--expert-rules` format** — a JSON list (or CSV with `label_a,label_b[,rule[,id]]`):

```json
[
  {"id": "abiotic_vs_concept", "labels": ["ABIOTIC ENTITY", "CONCEPT"],
   "rule": "A measured/named physical thing is ABIOTIC ENTITY; an abstract construct is CONCEPT."}
]
```

## How an iteration works

1. **Annotate** the working set under `(G_i, D_i)` — fresh subprocess
   (`cold_start_annotate.py`) so the pipeline's module-global tool state is reset
   between guidelines. `G_i` drives the Critic/Adjudicator; `D_i` drives the
   Annotator.
2. **Mine confusions** from the deliberation logs
   (`deliberation_history.analyze` → `layer34.json`) and compute **friction**
   (R1 disagreements, rounds-used rate, all-steps total).
3. **Metrics (§11.3):** if a held-out split is configured, annotate it under the
   same `(G_i, D_i)` (→ `heldout_deliberations.jsonl`) and compute the
   **agent-vs-expert held-out F1**; compute the **text delta** (rules added +
   embedding drift) and, if `--expert-rules` is given, **rule coverage**.
4. **Stop check (§11.3, before drafting):** `stopping_rule.decide_stop` —
   **GUARD** (held-out F1 down ≥2 iters → stop + flag echo-chamber, overrides) or
   **PRIMARY** (R1-disagreement relative reduction < eps for ≥2 iters → stop).
   On stop the loop breaks here, so the amender is never paid once converged.
5. **Select** the top-K confusions with count ≥ `--min-count` (and, when
   `--patterns entity`, entity-type confusions only).
6. **Draft** one amendment per confusion via `guideline_amender` — each must pass
   the operationality gate (a concrete if-then `decision_test` naming the
   competing labels), redrafting on failure.
7. **Apply** the accepted amendments to **both** artifacts:
   - `G_i → G_{i+1}`: each rule is **integrated into the section it concerns** —
     the amender routes it (verbatim `original_rule` → `target_section` heading →
     a heading naming one of the competing labels) and rewrites that section so
     the rule replaces the wording it supersedes. Sections nothing was routed to
     are copied through untouched, so the rewrite cannot silently drop or reword
     the rest of the guideline. Unroutable rules land in a single stable
     `## Disambiguation rules` section, itself rewritten on later iterations.
     A rewrite is accepted only if it keeps the section's content (word-count
     floor), still states each `decision_test` as a checkable rule naming the
     competing labels, and carries no changelog phrasing; otherwise it is
     redrafted (`--max-rewrite-retries`) and finally falls back to a
     deterministic merge at the end of that same section. `--integration append`
     restores the legacy dated-appendix behaviour.
   - `D_i → D_{i+1}` (append-only): each `decision_test` injected into the
     `Question` column of the rows for the two confused labels
     (`decision_table.py`, dedup'd).

**Why both?** `G_i` only feeds the Critic/Adjudicator; the Annotator reads the
decision table. Cold-starting and amending only the guideline would leave the
Annotator with full expert knowledge — so the table is cold-started and amended
too.

### Stop conditions

The loop stops on the **first** of:
- **Stopping rule (§11.3)** — the GUARD (held-out F1 decreased for
  `--stop-f1-guard-patience` consecutive iterations → echo-chamber, overrides) or
  the PRIMARY rule (relative reduction in R1 disagreements < `--stop-friction-eps`
  for `--stop-friction-patience` consecutive iterations). Disable with
  `--no-stopping-rule` (metrics still logged). The GUARD is only active when a
  held-out split is configured.
- `i_max` reached;
- no confusion with count ≥ `--min-count` (nothing to amend);
- zero amendments accepted in an iteration (artifacts can't change);
- a corpus leak detected in the drafted guideline (drafted text reproduces a
  verbatim n-gram from the corpus — the iteration's `G_{i+1}` is **not** promoted).

## Stopping rule (§11.3)

The dual rule lives in `stopping_rule.py` (unit-tested in
`../tests/test_stopping_rule.py`). Per iteration the loop logs four quantities;
**only the first two drive the decision**, the other two are monitored:

| Signal | Role | What it is |
|--------|------|------------|
| **Friction** | **PRIMARY stop** | Total round-1 Critic disagreements over the (fixed) working set, plus the rounds-used rate and all-steps total. The honest internal signal — it never peeks at the expert guideline. |
| **Held-out F1** | **GUARD (overrides)** | Agent-vs-expert micro F1 on a held-out split distinct from the working set (§11.7), reusing the Layer-1 offset matching. |
| Guideline text delta | monitoring | Rules added/changed + embedding-similarity drift vs the previous guideline. **Never a stop signal** — an LLM amender can rephrase/oscillate without converging. |
| Rule coverage | monitoring | Fraction of the enumerated expert disambiguations (`--expert-rules`) matched by an accepted `decision_test` for the same competing label pair (§11.5b). |

- **PRIMARY** — stop when the relative reduction in R1 disagreements between
  `G_i` and `G_{i+1}` is `< eps` for two consecutive iterations (friction
  converged).
- **GUARD** — if held-out F1 *decreases* for two consecutive iterations, stop
  immediately and flag echo-chamber behaviour; the report names the highest-F1
  iteration to recommend. *Friction dropping while F1 drops is the failure mode
  the guard catches.*
- **REPORT** — `stopping_report.{json,md}` show the friction trajectory
  **alongside** the held-out-F1 trajectory, so readers can see whether "the
  system decided it was done" coincided with "quality plateaued near the ceiling".
